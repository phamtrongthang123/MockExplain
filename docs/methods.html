Suggested methods

Methods currently covered by MockExplain and where to read more.

These are suggestions based on structural clues. MockExplain does not run the methods.

CONVOLUTION

CNNs

Filter inspection

Look at convolution kernels. Visualizing Weights ↗

Learn more

A convolution filter is a small set of weights applied across an input. Visualizing first-layer filters can reveal patterns such as edges or colors. Later filters combine learned features and are harder to interpret by looking at weights alone.

Needs: Convolution weights and their layout; no example input is required.

Grad-CAM

Highlight image regions associated with an output. Paper ↗

Learn more

For a chosen image and output, Grad-CAM uses gradients to weight convolutional feature maps and produces a heatmap. For example, it can show which parts of a photo are associated with a “cat” score.

Needs: A runnable model, input, target output, feature maps, and gradients. The map is coarse and does not prove causation.

ATTENTION

Transformers

J-lens

Read language-model activations in vocabulary space. Paper ↗ · Code ↗

Learn more

The Jacobian lens maps an intermediate activation toward the model’s output space using an average of how later layers respond to small changes. It then ranks vocabulary tokens associated with that activation.

Needs: A compatible model, tokenizer, input, activations, and a fitted lens. Its token readout is approximate and may miss concepts that span multiple tokens.

Logit lens

Read intermediate activations as vocabulary predictions. Tuned Lens paper ↗ · Code ↗

Learn more

The logit lens applies the model’s output readout to an intermediate layer, giving a vocabulary distribution at that point. Comparing layers can show how a possible next-token prediction changes.

Needs: A runnable language model, input, activations, and compatible output readout. Intermediate layers may use a different representation, so the readout can mislead. A tuned lens trains a separate translator to address this.

Sparse autoencoders (SAEs)

Find sparse features in model activations. Paper ↗

Learn more

An SAE learns to reconstruct activations using a larger set of features, with only a few active at once. Looking at examples that activate a feature can help a researcher form a hypothesis about what it represents.

Needs: Representative activations and an SAE trained for the model and layer, or new training. Features can be ambiguous and depend on the training data.

Activation inspection

Inspect activations at layers or heads. TransformerLens ↗

Learn more

Run inputs through the model and record intermediate values, such as layer activations or attention patterns. Comparing examples may reveal where a pattern appears or changes.

Needs: A runnable model, representative inputs, and access to its internal activations. A pattern alone does not establish what caused the output.

RULES

How suggestions are chosen

  • Convolution clues suggest filter inspection and Grad-CAM.
  • Attention clues suggest SAEs and activation inspection. When embeddings and a possible vocabulary head are also found, J-lens and logit lens replace activation inspection.
  • For convolution-and-attention hybrids, suggestions are limited to filter inspection, Grad-CAM, J-lens when language clues are present, and SAEs.
  • Unknown structures receive no method suggestion.

Clues are not proof of model family or method compatibility. Open Details in the app for each method’s requirements and limits.
